# Codex 작업지시 — M10 몹 애니메이션 프레임 오류 (2026-11-23)

## 증상
플레이 중 일부 몹 애니메이션이 이상함 (다른 몹 프레임이 섞이거나, 이동 중 멈춤).

## 원인 (Claude 진단)
`Assets/Editor/DungeonTools/M10EnemyVisualCatalogBuilder.cs` 의 `LoadFrames` 가 `AssetDatabase.FindAssets` 이름 검색(부분 일치)을 쓴다.

| 몹 | 현재 결과 |
|---|---|
| zombie | `zombie_idle_anim` 검색 → **tiny_zombie + big_zombie** 프레임 8장이 섞임 (크기도 다름). run 도 동일 |
| slug | idle/run 파일 없음 → `slug_anim` 폴백 → **slug + tiny_slug** 섞임 |
| ice_zombie, muddy, necromancer, swampy, tiny_slug | `_anim_f*` 만 있음 → idle 만 채워지고 **runFrames 비어 있음** |
| zombie (원본) | 실제 파일은 `zombie_anim_f1,f2,f3,f10` — 문자열 정렬 시 f10 이 f2 앞에 옴 |
| chest_mimic | `chest_mimic_open_anim_f0-2` 만 있음 → idle/run 모두 여는 애니 |

## 수정
1. `FindAssets` 부분 일치 대신 Frames 폴더 파일명을 정확히 매칭:
   - 1순위 `^{key}_{action}_anim_f(\d+)$`
   - 2순위(액션 없는 몹) `^{key}_anim_f(\d+)$` → idle·run 모두 같은 프레임 사용
   - chest_mimic: idle = `chest_mimic_open_anim_f0` 1장(닫힌 상자) 정지, run 은 open f0-2 (임시. 이상하면 사용자 결정)
2. 프레임 정렬은 `f` 뒤 숫자 기준 **정수 정렬**.
3. 카탈로그 재생성 (`Tools/Dungeon/M10/Rebuild Enemy Visual Catalog`).
4. Validate Data 에 검사 추가: m10_enemies.csv 의 모든 sprite_key 가 idle ≥ 1, run ≥ 1, 모든 프레임 이름이 해당 key 로 시작(다른 key 섞임 금지).
5. 큰 스프라이트(ogre, big_zombie, orc_warrior, big_demon)와 16x16 몹의 pivot/위치가 타일에 맞는지 확인. 어긋나면 보고만 (수치 임의 변경 금지).

## 지키기
- 새 Canvas·Singleton 금지, `ProjectSettings/PackageManagerSettings.asset` 커밋 금지.

- 카탈로그 `.asset`/`.meta` 공백 diff 만 생기면 커밋 제외.
