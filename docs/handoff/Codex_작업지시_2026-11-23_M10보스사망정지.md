# Codex 작업지시 — M10 보스에게 사망 시 진행 정지 재발 (2026-11-23)

## 증상 (사용자 Play)
M10 보스(5F 미믹 또는 10F orc_warrior)에게 사망하면 진행이 멈추고 Dead 결과 화면으로 넘어가지 않는다.
BUG-032, BUG-034와 같은 증상의 재발이다.

## 먼저 확인
1. `%LOCALAPPDATA%\Unity\Editor\Editor.log`에서 마지막 사망 구간의 `[DeathFlow]` 로그, 예외, 반복 로그를 확인한다.
2. Unity 전체가 응답 없음(무한 루프)인지, 게임만 멈춘 것(코루틴 미실행·입력 대기)인지 구분해서 보고한다.

## 의심 지점 (Claude, 코드만 보고 추정)
- `PlayerTurnActor.TakeDamage` → `isDead=true` → `ExpeditionManager.RequestDeathResolution()` → `yield return null` 뒤 `CompleteDeath()`.
  스케줄러가 사망 후에도 보스·적 턴을 같은 프레임에서 동기적으로 계속 돌리면 다음 프레임이 오지 않는다(BUG-032 원인과 같은 구조).
- M10에서 추가된 경로가 사망 판정 이후에도 턴을 진행시키는지 확인:
  `TickManager`(258행 `M10RunProgression.AdvanceTo`), M10 보스 행동, 레벨업·포션 회복, 엘리트·보스 스케일/비주얼.
- `PlayerTurnActor.Update()` 경로(291행)가 M10 변경 이후에도 살아 있는지.

## 수정 원칙
- Player 사망이 확정되면 그 즉시 스케줄러가 더 이상 턴을 진행하지 않거나, 같은 프레임 안에서 `CompleteDeath()`가 한 번만 실행되게 한다.
- 단일 사망 / 광역 사망 / 포션 회복 중 사망 / 레벨업 직후 사망 / 미믹·orc_warrior 각각 회귀 확인.
- QA 재현 도구가 필요하면 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 안에 넣고 `docs/QA_DEBUG_TOOLS.md`에 기록.
- `QA/BUGS.md`에 새 BUG 번호로 기록 (BUG-032·034 관련 표시).

## 지키기
- 새 Canvas·Singleton 금지, `ProjectSettings/PackageManagerSettings.asset` 커밋 금지, `preloadedAssets` 삭제되면 원복.

## 추가 (사용자 확인 2026-11-23): Unity 에디터 전체가 응답 없음 → 메인 스레드 무한 루프
- `TickManager.AdvanceSchedule()`의 do-while은 AI가 `OnTurnStart` 안에서 즉시 `CompleteTurn`을 부르면 계속 돈다.
  Player가 죽어서 차례를 안 받거나(비활성/해제) 즉시 완료하면, 남은 보스·적이 매 바퀴 즉시 완료해서 **루프가 영원히 안 끝난다**.
  `RequestDeathResolution()`은 `yield return null` 뒤에 처리하므로 그 다음 프레임이 오지 않는다.
- 로그가 끝없이 반복되는 `[시각] {보스}/Attack...` 줄이 있는지 Editor.log에서 확인 (있으면 확정).
- 수정 방향 (둘 다):
  1. `AdvanceSchedule` 반복 조건에 `PlayerTurnActor.Instance == null || IsDead || !ExpeditionSession.IsActive` 이면 중단 + 사망이면 그 자리에서 `CompleteDeath()` 1회.
  2. 안전장치: 한 번의 `AdvanceSchedule` 안에서 반복 횟수 상한(예: 10,000) 초과 시 경고 로그 남기고 탈출 (값은 상수, 이유 주석).
- 미믹·orc_warrior가 `OnTurnStart`에서 Player 대상이 없거나 죽었을 때도 0이 아닌 Tick으로 완료하는지 확인.
